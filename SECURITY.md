# Security Policy

## Supported scope

CyberOS is experimental software. Security reports are welcome for the ISO build process, live environment, installer, included configuration, and project automation.

## Reporting a vulnerability

Please do not publish exploitable details in a public issue.

Use GitHub's **Report a vulnerability** action on this repository if private vulnerability reporting is enabled. If it is unavailable, contact the repository maintainer through the contact method listed on the GitHub profile and include:

- affected version or commit;
- affected component and environment;
- steps to reproduce;
- expected and actual behavior;
- potential impact;
- a proposed mitigation, if known.

Do not include passwords, access tokens, private keys, or other secrets in a report.

## Scope and response

The maintainer will make a best-effort attempt to acknowledge valid reports, assess impact, and coordinate a fix and disclosure. No response-time SLA is promised while the project is maintained by volunteers.

## Safe use

Do not treat an experimental ISO as a hardened operating system. Review the source and build output before use. Keep backups and test installation only in a disposable VM or on a disk that may be erased.
